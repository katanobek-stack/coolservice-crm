# P&L workspace

The owner requests the same professional, colourful, convenient workflow used in Reports and Monitoring. The same-principle request delegates routine design choices and standing commit/publish authority; implement inline without repeating approval gates.

Use React/TypeScript, existing Firebase paths, XLSX and Manrope. No dependencies, schema migration, permission expansion or production QA records. Desktop and 480px only, never 320/390.

Chosen approach: replace the unfiltered current-month page with a scoped financial workspace around pure month calculations and existing records. A cosmetic refresh retains the period mismatch; a new accounting system would change financial semantics and is outside scope. Keep existing completed-repair revenue (repairStatus=done, financial month uses closedAt then date), not cash accounting. Explicitly distinguish it from actual payment. Preserve historical fixed-cost snapshots using resolveFixedCosts; when missing/partial, state which totals use current configuration. Commission category only, other expense categories retained untouched. No invented income, taxes or margins.

Navy #14324a header, pale blue #eaf1f8 canvas, white outlined fields #7e93a8, teal #087f75 income, rust #b04439 expenses, blue #245b93 results. Profit/loss uses text and sign as well as colour. One month control drives all summary, details and export; previous/current/next navigation. Views: Overview with calculation bridge and monthly table, expense journal with kind/search/sort, repair revenue details, current fixed-cost settings. Preserve drafts when switching views or losing read sources. Editing dates/months are explicit and independent from viewing filters; success names saved period.

Operations: add dated purchases with required description; add commissions assigned to explicit month; save electricity bill with fresh-value conflict guard (zero allowed); edit current boxes/salaries/tariff using captured original configuration; explain settings apply to current/future months, previous months remain frozen. Validate full decimal, finite safe cents, nonnegative (positive purchases/commissions), zero settings and electricity. Destructive removal requires inline review with exact target and amount. Idempotent purchase/commission IDs across uncertain retries; no automatic retry for a new user action. Errors keep inputs and unlock action. All writes use existing backend role rules and transaction guards, never overwrite unrelated finance entries.

All financial sources (clients/freezers/finance/expenses) must be ready before displaying totals or enabling writes/export; a read failure must not show a misleading zero or remount drafts. Explicit loading/error/empty/success states. Unknown roles and mechanics cannot view P&L; existing staff pl_panel flag retained. Export selected-month summary + detail with numeric amounts and the same formulas as the UI. Journal filtering must not change KPI totals/export.

Verify pure month totals, history and fallback, fractional amounts, cancelled/ready/legacy records, unknown sources, filters, export and real transaction conflict/retry/denial. Render actual components on synthetic data with writes blocked; no live financial mutations.
