# ДДС в CRM — план реализации

**Цель:** отдельная страница реального денежного учёта с планированием и Excel, без выдуманной себестоимости склада.

**Решение:** работаем в текущей копии, не затрагивая изменения телеметрии. Отдельные коллекции `cashflowAccounts` и `cashflowEntries`. Один перевод — один документ с двумя счетами. Суммы в целых копейках. Нет автоматического признания оплаты по закрытию ремонта или настройке зарплаты. Источники дают предложения к заполнению с подтверждением даты и счёта. Плановый платёж проводится в факт в том же документе. Фактическая операция неизменяема; ошибочную можно аннулировать с причиной и историей.

**Доступ:** owner, manager и admin с разрешённой финансовой панелью; те же проверки на серверных правилах. Механикам данные ДДС не доступны.

**План:**

- [x] Чистая расчётная логика и тесты: копейки, даты, перенос остатков, частичные оплаты, планы, внутренние переводы, аннулирование, источники и Excel.
- [x] Транзакционные записи, повторные запросы с устойчивым ID, правила доступа и интеграционные тесты.
- [x] Страница в стиле P&L: обзор, операции, план, источники, счета; мобильная версия, состояния ошибок и загрузки.
- [x] Навигация desktop/mobile, Excel выбранного периода с полными регистрами и параметрами отчёта.
- [x] Проверки типов, unit-тесты, сборка, правила в эмуляторе при доступности; проверка интерфейса.

**Результат проверки:** typecheck и production-сборка успешны; полный `npm test` с локальным эмулятором — 351 проверка без ошибок. Интерактивный браузерный сценарий на изолированных данных прошёл, Excel прочитан обратно и проверен. Независимый обзор кода не выявил существенных ошибок. Ограничение первой версии: существующий план проводится целиком; частичные платежи оформляются отдельными планами. Инструкция — `docs/cashflow.md`. Пользователь отдельно разрешил commit/push/deploy; правила опубликованы 10.11.2026 перед публикацией интерфейса через main.

**Не включено:** склад деталей, FIFO, прибыль по отдельным работам, синхронизация банка, автоматическая выплата зарплаты, публикация и commit/push.

**Особые проверки:** начало учёта внутри месяца, отрицательный остаток, будущее поступление в плане, неполная оплата заказа, перевод при фильтре по одному счёту, потеря соединения, повтор сохранения, снятое разрешение, сумма ремонта без цены.
